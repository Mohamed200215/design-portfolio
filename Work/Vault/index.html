01 / OVERVIEW

What VAULT is

VAULT is a concept marketplace for buying, selling, and bidding on high-end sneakers and streetwear — StockX or GOAT's category, built as a design/front-end exercise, not a real business. It's for the resale crowd: people who already know what a "colorway" is and would rather scroll a dark, image-heavy storefront than a spreadsheet with a logo on it.

It's since grown a real backend: Supabase handles auth, wishlist, cart, and orders for signed-in users, with row-level security scoping every table to its owner, while guests still get the original client-side experience via localStorage. Same feature set either way — home, marketplace listings with filtering/sorting/search, product pages with size/colorway selection, a cart, and now real sign-in/sign-up instead of a fake local session.

02 / THE PROBLEM

Where resale platforms fall short

StockX and GOAT are built for trust and liquidity, not identity — they read like financial terminals with sneaker photos on them. Grailed has more personality but leans messy and peer-to-peer, which cuts trust. Neither feels curated, like someone with taste picked what's on the shelf.

VAULT's bet: resale doesn't have to choose between "feels legit" and "feels like a brand" — a dark, editorial interface can still do the trust-signalling work (condition ratings, "Authenticated" language, Hot / New / Limited / Used badges) that makes people comfortable paying real money for a used shoe.

03 / DESIGN DIRECTION

Why neo-brutalism

Neo-brutalism fits streetwear because the culture already runs on the same grammar: stark contrast, oversized type, hard edges, "if you know you know" exclusivity. DESIGN.md calls for a dark-first "lights-out showroom" with sharp 0px-radius corners, so the interface recedes and lets product photography do the talking.

05 / DESIGN SYSTEM

Components, spacing, states

The system is enforced in code, not just described. .neo-border (a flat 1px #333 stroke) marks the hero's bid card and home page product cards, and cards are properly componentized — .product-card / .product-card-content / .product-card-footer pin the price/CTA row to the bottom regardless of description length.

States are real: .filter-active, .filter-pill.active, and .option-selected share the same electric-blue-fill treatment, so "selected" looks identical whether it's a category pill, sort button, or size chip:

FLAGGED: DESIGN.md specifies hard 0px-radius corners everywhere, and the home page respects that — but listings.html and product.html drifted to rounded-3xl cards and rounded-full buttons. A real gap between the documented system and the shipped pages, not a deliberate variant.
06 / BUILD NOTES

Front-end approach

Rebuilt on Vite + TypeScript + React: static HTML per page for markup and SEO, React islands for the interactive pieces (cart, wishlist, product options), and a typed data layer backed by Supabase — Postgres tables with row-level security for auth, wishlist, cart, and orders, falling back to localStorage for guests and merging a guest's items into their account on sign-in. Tailwind's still CDN-loaded, with a token config that mirrors DESIGN.md. A Vitest suite (unit tests plus React Testing Library component tests) and ESLint/Prettier run in CI on every pull request.

Two details worth calling out: card clicks use one delegated document-level listener rather than per-card listeners, so it survives back-button/bfcache and doesn't care whether a link is product.html?id= or something a host rewrote. And the homepage runs a scripted "vault door" opening animation over the hero — theatre that earns the name, now gated to play once per browser session instead of replaying every time you click back to the logo.

07 / REFLECTION

What I'd test, what I'd fix

This is a self-initiated concept project — no real users, no interviews, no usage data, and I'd rather say that plainly than dress it up.

If I tested it with real people, I'd want to know whether the size/colorway-required flow reads as helpful friction or just an annoying wall, and whether "Place bid" is discoverable at all — right now it's a plain outlined button with no visual weight next to the hero image, and I have no evidence anyone would notice it's clickable. I'd also want a first-click test on "Latest drops" vs. "Marketplace" in the nav, since I assumed what those labels mean to a resale audience without checking it.

On the build side, next fixes are the rounded-corner drift between home and listings/product, and the bid-persistence bug — both concrete, verifiable issues, not guesses.
